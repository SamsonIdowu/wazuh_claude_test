Wazuh Testing Infrastructure

Improvement recommendations for multi-version testing (4.14.6 and 5.0.0)

Current State vs Proposed

✓ Currently Working

  • Wazuh 4.14.6 + TheHive 5 on AWS
  • 8 documented gotchas in runbook
  • Fresh deploy, integration, enrollment, dashboard tests
  • Evidence-based verification (never trust without proof)

→ Proposed Additions

  • Dual-version support (4.14.6 + 5.0.0)
  • Version-specific runbooks with breaking changes documented
  • Documentation testing mode for validating official docs
  • Test matrix (version × scenario) with clear coverage tracking
  • Automated upgrade testing (4.14.6 → 5.0)
  • Enhanced cost tracking and failure diagnostics

8 Major Improvements

1. Dual-Version Support

Version-Specific Modules

Problem: Single variable doesn't capture installation differences.

Solution: Organize into terraform/versions/v4_14_6/ and v5_0_0/.

2. Deployment Runbooks

Version-Specific Documentation

Problem: Only 4.14.6 runbook exists.

Solution: Create test/deployments/wazuh_5_0_0/RUNBOOK.md with research findings.

3. Documentation Testing

Validate Official Docs

Problem: No way to verify docs are accurate against live deployment.

Solution: New DOCUMENTATION_TEST_TEMPLATE.md for systematic validation.

4. Test Matrix

Version × Scenario Tracking

Problem: Single test; no coverage visibility.

Solution: test_scenario variable for fresh_deployment, eol_detection, etc.

5. Upgrade Testing

Migration Path Validation

Problem: No clear 4.14.6 → 5.0 upgrade path documented.

Solution: UPGRADE_TEST_TEMPLATE.md + upgrade_from_version variable.

6. Cost Tracking

Visibility & Attribution

Problem: No cost visibility or per-test attribution.

Solution: Add test_id variable + tags + cost estimates in outputs.

7. Documentation Structure

Organized by Version

Problem: Version info scattered; hard to navigate.

Solution: Organize into test/deployments/{version}/ structure.

8. Version Matrix

Roadmap Visibility

Problem: Users don't know which tests work on which versions.

Solution: Add version support matrix to README showing status & coverage.
