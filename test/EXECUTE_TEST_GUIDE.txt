🎯 WHAT IS THIS?

A self-executing test automation system where you simply type "execute test"
and Claude automatically:
  1. Reads your Google Drive document
  2. Creates test implementation steps
  3. Deploys infrastructure
  4. Runs tests end-to-end
  5. Generates test results

🔄 TEST EXECUTION PHASES

When you say "execute test", Claude follows this procedure:

Phase 1: Document Analysis (5 min)
  └─ Read AUTOMATED_TEST_TEMPLATE.md
  └─ Extract Google Drive document link
  └─ Read the document to understand requirements

Phase 2: Test Planning & Infrastructure Analysis (10 min)
  └─ Extract infrastructure requirements from document
  └─ Identify instance types, OS versions, component versions, storage
  └─ Generate terraform/terraform.tfvars from requirements
  └─ Update terraform variables if new parameters needed
  └─ Map blog post steps to test procedures
  └─ Create test-implementation-steps.md with infrastructure details

Phase 3: Infrastructure Setup (10 min)
  └─ Run setup.ps1 (auto-detect your IP)
  └─ Run terraform init && terraform plan && terraform apply
  └─ Wait for services (5-10 minutes)

Phase 4: Test Execution (10-15 min)
  └─ SSH to Wazuh server
  └─ Deploy configurations
  └─ Run each test step sequentially
  └─ Capture results

Phase 5: Results & Verdict (5 min)
  └─ Create test-verdict.md (Pass/Fail/Partial)
  └─ Create test-details.md (findings)
  └─ Generate summary

Phase 6: Cleanup (auto-managed)
  └─ Resources auto-terminate after 1 hour
  └─ Or manually run: terraform destroy
  └─ Or extend TTL in terraform.tfvars

📊 WHAT GETS GENERATED

After "execute test", check Results/:

Results/test-implementation-steps.md

  • Documents any configuration changes

Results/test-verdict.md
  • Overall verdict: PASS / FAIL / PARTIAL
  • Summary of what worked and what didn't
  • Quick reference for main findings
  • Recommendations for next steps

Results/test-details.md
  • Complete findings and detailed logs
  • Output from each test step
  • SSH command results
  • Configuration changes made
  • Any errors encountered

Results/execution-log.txt
  • Timeline of everything that happened
  • Timestamps for each phase
  • Status of each component
  • Resource URLs and connection details

⚙️ CUSTOMIZATION OPTIONS

Optional parameters in AUTOMATED_TEST_TEMPLATE.md:

Deployment Configuration:
  • aws_region (default: us-east-1)
  • wazuh_version (default: 4.14.6)
  • resource_ttl_minutes (default: 60)
  • enable_auto_termination (default: true)

Test Scope:
  • Mark which tests to run
  • Skip infrastructure if already deployed
  • Extend test coverage

Test Timeout:
  • Adjust how long to wait for services
  • Configure retry behavior

❓ FAQ

Q: How do I start?
A: Update the Google Drive link in AUTOMATED_TEST_TEMPLATE.md, then say
   "execute test"

Q: What if I need to stop mid-test?
A: Say "stop test" - infrastructure stays running, you can clean up manually

Q: How long does it take?
A: Usually 20-40 minutes total (5 min analysis, 10 min deploy, 15 min tests)

Q: What if deployment fails?
A: Claude will report the error. Fix the issue and run "execute test" again

Q: Can I run tests multiple times?
A: Yes. Update the Google Drive link and run "execute test" again

Q: How do I use different infrastructure settings?
A: Edit the optional parameters section in AUTOMATED_TEST_TEMPLATE.md
